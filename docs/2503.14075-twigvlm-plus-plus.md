## 2. 核心贡献概述

- 中文版：这篇论文把早期 TwigVLM 从“一个浅层 twig 同时做 token pruning 信号和 speculative draft”扩展为 TwigVLM++：用 P-Head / D-Head 解耦 pruning 与 next-token prediction，用 teacher distillation 加 pruning-oriented RL 直接优化保留视觉 token 的策略，并用 tree-based self-speculative decoding 提升长回答生成速度。
- 英文版：“TwigVLM++ improves pruning quality via a two-stage training paradigm combining a distillation learning stage and a pruning-oriented reinforcement learning stage.”（出自 abstract 最后一段）

## 4. 学术贡献清单

### 4.1 动机的发现与阐明

论文的出发点不是单纯说视觉 token 很冗余，而是把 VLM 推理拆成 prefilling 与 decoding 两段，指出已有 visual token pruning 主要省 prefilling，却对长回答的 decoding 帮助有限。作者用两个 pilot study 支撑这个判断：第一，早层 attention 对 prompt 不敏感，拿它选视觉 token 容易保留错误区域；第二，生成长度 $S$ 增大时 decoding time 近似线性上升，$S \ge 32$ 后 prefilling time 反而不再是主要瓶颈。

![Figure 2: attention quality for token selection](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig2.pdf)

图解：图 2 固定 pruning layer $K=2$，只改变用于选 token 的 attention layer depth $D$。曲线显示 $D$ 越靠后，RelAcc 越接近原始 LLaVA-1.5-7B；右上角可视化还显示 $D=2$ 对两个不同问题几乎选同一区域，而 $D=18$ 会随 prompt 转向旗帜或象背装备。这张图是 TwigVLM 需要“浅层位置、深层语义信号”的核心证据。

![Figure 3a: decoding time with varied response length](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig3a.pdf)

图解：图 3a 把 prefilling time 作为灰色虚线，把不同 response length 的 decoding time 画成柱状。随着 $S$ 从 2 增到 128，decoding time 迅速超过 prefilling，说明只削短输入视觉 token 无法覆盖长回答场景的主要耗时。

![Figure 3b: prefilling and decoding time costs](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig3b.pdf)

图解：图 3b 对比 LLaVA 与 LLaVA+FastV 在 $S=32$ 时的耗时。FastV 明显降低 prefilling，但 decoding 几乎没有变，因为 KV-cache 已经削弱了 self-attention 部分的收益，且 FFN 仍要逐 token 执行。这个观察引出 TwigVLM 把 token pruning 与 self-speculative decoding 放进同一框架。

### 4.2 方法的创新

原始 TwigVLM 的创新是“grow a twig”：冻结 base VLM，在第 $K$ 层后接一个小型 twig block，训练成 shallow VLM $\mathcal{M}_s$。它在 prefilling 阶段输出更接近 prediction head 的 token selection signal，在 decoding 阶段作为 draft model 与 base VLM 共享前 $K$ 层计算和 KV-cache。

v3 的 TwigVLM++ 扩展主要有三点。第一，multi-head twig 增加专用 P-Head，与 D-Head 解耦，避免同一个 attention map 同时承担 pruning 和 next-token prediction。第二，两阶段训练先用 NTP、PredKL、AttnKL 做 distillation，再只更新 P-Head，用 GRPO 风格的 pruning-oriented RL 直接最大化 pruning 后 reference answer 的 log-likelihood。第三，解码从 sequence-based SSD 换成 tree-based SSD，一次构造多条候选路径，用 tree attention 并行校验，以提高每次 target verification 接受的 token 数。

![Figure 1: TwigVLM and TwigVLM++ overview](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig1ab.pdf)

图解：图 1ab 把 TwigVLM++ 相对 TwigVLM 的变化画得很直观：左边是 base VLM 与 learnable twig 共享低层；中间是 TwigVLM 用 twig attention 改善 pruning 并用 SSD 加速生成；右边是 TwigVLM++ 的 P-Head / D-Head 与 tree-based SSD。注意 P-Head 是 v3 的核心增量，它让 pruning 目标可以被单独训练。

![Figure 5: multi-head twig and two-stage training](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig5.pdf)

图解：图 5 展示 TwigVLM++ 的完整训练路径。stage-1 从 base VLM 蒸馏 prediction distribution 与 attention distribution；stage-2 只训练 P-Head，把多组 token selection mask 经 base VLM 打分后转成 GRPO loss。这里的 reward 来自 reference answer log-prob，而不是外部 verifier 或人工偏好分数。

### 4.3 实验上的核心结论

在 LLaVA-1.5-7B 上，保留平均 64 个视觉 token，即 pruning 88.9% 时，FastV 只有 77.0% RelAcc，VisionZip 为 93.3%，TwigVLM 为 96.0%，TwigVLM++ 提升到 97.7%。在长回答 MM-Vet 上，同样 $\bar{R}=64$，FastV 与 VisionZip 只有约 104%/106% RelSpd，TwigVLM 达 154%，TwigVLM++ 达 197%。在 Qwen2.5-VL-7B 的图像和视频 benchmark 上，TwigVLM++ 在 aggressive pruning 下比 VisionZip 的 RelAcc 高 6.0 个点，同时 RelSpd 接近 193%，说明 multi-head + RL 对强 base VLM 更有价值。

![Figure 1c: accuracy and generation speed comparison](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig1c.pdf)

图解：图 1c 固定 LLaVA-1.5-7B 与 88.9% pruning ratio，直接比较 FastV、TwigVLM、TwigVLM++。TwigVLM 相对 FastV 的主要提升是准确率从 77.0% 到 96.0%；TwigVLM++ 相对 TwigVLM 的准确率只再升 1.7 点，但速度从 60.2 tok/s 到 77.3 tok/s，说明 v3 的 tree-based SSD 对吞吐的贡献更突出。

## 5. 写作故事线

论文的故事从一个现实问题开始：VLM 能力变强，但视觉 token 数量大，Transformer 复杂度随序列长度增长，部署很慢。作者没有停留在“删 token 即可加速”，而是先指出 FastV 这类方法的两个盲点：早层 attention 不是好的 task-aware selection signal，且视觉 token pruning 主要优化 prefilling，不能解决长回答 decoding 的逐 token 串行瓶颈。

第 3 节的两个 pilot study 是关键转折。作者先证明晚层 attention 更适合选 token，但直接用晚层 attention 会先跑很多层，失去加速意义；于是第 4 节提出 TwigVLM：在早层长出一个浅 twig，让它用很少计算模拟“更靠近 prediction head 的语义信号”。同一个 twig 在 prefilling 时做 TTP，在 decoding 时做 SSD draft，因此同时覆盖两个阶段。

v3 的新增故事线从“原始 TwigVLM 的 pruning 能力只是 AR training 的副产物”展开。第 5 节引入 TwigVLM++：既然 pruning 和 draft prediction 是不同任务，就把 P-Head 与 D-Head 拆开；既然 P-Head 需要更明确的 pruning 目标，就用 base VLM 的 prediction/attention 蒸馏做 warm-up，再用 reference log-likelihood 作为 reward 训练 P-Head；既然 sequence SSD 每轮只覆盖一条 draft 路径，就改用 tree-based SSD 并行覆盖多条候选路径。实验部分再按 LLaVA-1.5、LLaVA-NeXT、Qwen2.5-VL、速度图和 ablation 逐步证明这些设计分别解决了准确率、长回答速度和强模型泛化问题。

## 7. 批判性分析

**与 FastV 的关系。** FastV（*An Image is Worth 1/2 Tokens After Layer 2*, arXiv:2403.06764, https://arxiv.org/abs/2403.06764）提出在 VLM 早层用 attention pruning 视觉 token，是 TwigVLM 的直接问题背景。TwigVLM 并不是推翻 FastV 的 pruning 框架，而是替换其核心信号源：FastV 用第 $K$ 层自己的 early attention 选 token；TwigVLM 用训练好的 twig 最后一层 attention / TwigVLM++ P-Head score 去指导同一位置的 pruning。因此它更像“FastV 式早剪枝 + 一个学习出来的晚层代理信号 + decoding 阶段 SSD”的组合。

**与 SparseVLM 的关系。** SparseVLM（*SparseVLM: Visual Token Sparsification for Efficient Vision-Language Model Inference*, arXiv:2410.04417, https://arxiv.org/abs/2410.04417）强调 training-free、text-guided token optimization、rank-based sparsification 和 token recycling。TwigVLM 相比 SparseVLM 的优势是可以通过训练得到更强 pruning signal，并把 decoding 加速纳入框架；代价是需要额外 twig 参数、SFT 数据、蒸馏计算和 RL stage。若部署方没有训练数据或不能改模型权重，SparseVLM / VisionZip 这种无训练方案仍然更轻。

**与 VisionZip 的关系。** VisionZip（*VisionZip: Longer is Better but Not Necessary in Vision Language Models*, arXiv:2412.04467, https://arxiv.org/abs/2412.04467）在 visual encoder 侧就压缩视觉 token，优点是模型无关、训练免费、对多轮对话和高分辨率输入友好。TwigVLM 的论点是这类视觉编码阶段 pruning 缺少 prompt awareness，而 Fig. 2/6/9 用可视化展示 prompt-aware token selection 的价值。不过，VisionZip 在 LLaVA-1.5 和 LLaVA-NeXT 表格里仍然很强，特别是 TeX 里出现的 `VisionZip‡` 变体接近 TwigVLM；论文没有在可见 TeX 段落解释 `‡` 的具体设置，这是结果复现时需要复核的细节。

**与 speculative decoding 前作的关系。** TwigVLM 的 SSD 来自 speculative decoding（*Fast Inference from Transformers via Speculative Decoding*, arXiv:2211.17192, https://arxiv.org/abs/2211.17192）和 self-speculative decoding / LayerSkip（*LayerSkip*, arXiv:2404.16710, https://arxiv.org/abs/2404.16710）。TwigVLM 的真正新意不在“draft-then-verify”本身，而在于为 VLM 训练一个共享早层的 twig draft，并让它同时服务 visual token pruning。需要注意，论文说 SSD 不改变 target model 输出，这个“lossless”只相对于 pruning 后的 target path 成立；整个 TwigVLM 相对原始 base VLM 的准确率仍会被 TTP/FinalWipe 改变。

**与 tree-based / multi-head decoding 前作的关系。** TwigVLM++ 的 tree-based SSD 与 SpecInfer（*SpecInfer*, arXiv:2305.09781, https://arxiv.org/abs/2305.09781）和 Medusa（*Medusa*, arXiv:2401.10774, https://arxiv.org/abs/2401.10774）的“多候选路径 + tree attention verification”关系很近。P-Head / D-Head 的“多头”不是像 Medusa 那样多个 future-token decoding heads，而是将 pruning score head 与 standard decoding head 分离；因此名称相似但功能不同。v3 还引用了 2025 年的 VLM speculative work，如 Spec-LLaVA（*Spec-LLaVA: Accelerating Vision-Language Models with Dynamic Tree-Based Speculative Decoding*, arXiv:2509.11961, https://arxiv.org/abs/2509.11961），说明到 v3 时“VLM + tree speculative decoding”已经不是孤立想法；TwigVLM++ 的区分点是把它和 trained visual token pruning/P-Head 放在同一模型里。

**脆弱 claim 与复现实验风险。** 第一，TwigVLM++ 的 RL reward 是 reference answer 的平均 log-prob，而不是下游 benchmark 的真实答题 reward；它可能偏向 SFT-style answer likelihood，对开放式或多答案任务不一定等价于更好的任务正确率。第二，作者主要在 greedy/argmax 风格的 verification 下讨论“同输出”，采样策略、温度、beam search 或多轮对话缓存复用下的 exactness 需要代码级确认。第三，Qwen2.5-VL 的 stage-1 训练使用 MAmmoTH-VL-10M 的 5M 单图样本作为替代数据，这对工业部署是合理工程选择，但也意味着方法的性能部分来自较大额外训练数据，不是纯 plug-and-play。第四，速度结果依赖生成长度分布、GPU 并行效率、batch size 与实现细节；TextVQA 短回答场景下 TwigVLM++ 的速度优势明显小于 MM-Vet 长回答场景，说明它的最大价值域是长生成而非所有 VQA。

## 8. 方法细节

### 算法流程

**原始 TwigVLM。** 给定 $L$ 层 base VLM $\mathcal{M}_b=\{\mathcal{T}_l\}_{l=1}^{L}$，在第 $K$ 层后接 $T$ 层 twig block $\{\mathcal{G}_t\}_{t=1}^{T}$，形成 shallow VLM $\mathcal{M}_s=\{\mathcal{T}_k\}_{k=1}^{K}\cup\{\mathcal{G}_t\}_{t=1}^{T}$。训练时冻结 base VLM 与共享低层，只更新 twig block 和 twig head；推理时：

1. Prefilling：输入 image tokens 与 prompt tokens 先过 base VLM 前 $K$ 层，得到 $\mathbf{X}^{(K)}_{\mathcal{M}_b}$；再过 twig block 得到最后 twig layer attention，用 TTP 选择 $R$ 个视觉 token。
2. Base continuation：保留 token 继续过 base VLM 后续层；在 late layer $K_f$ 后执行 FinalWipe，把所有剩余视觉 token 删除。
3. Decoding：twig shallow model 作为 draft model 生成多个 draft token，base VLM 作为 target model 并行验证；两者共享前 $K$ 层计算与 KV-cache。

![Figure 4a: TwigVLM training](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig4a.pdf)

图解：图 4a 展示原始 TwigVLM 的训练：twig layers 从 base VLM 的 $K+1$ 到 $K+T$ 层初始化，twig head 从 VLM head 初始化；下方共享低层冻结，上方 twig 更新。这个初始化策略在消融中显著影响 TokAR 与 RelSpd。

![Figure 4b: TTP in prefilling](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig4b.pdf)

图解：图 4b 展示 TTP 的数据流：twig 不是直接替换 base VLM，而是为 base VLM 第 $K$ 层输出的视觉 token 提供 selection signal。这样既保持早剪枝带来的计算节省，又让 token selection 更接近深层语义。

![Figure 4c: SSD in decoding](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig4c.pdf)

图解：图 4c 展示 shallow twig draft 与 deep target 的关系。draft model 先给出若干 token，target model 校验正确前缀并补一个 bonus token；错误处之后的 draft 被丢弃。共享前 $K$ 层是 TwigVLM 相比外部小 draft model 的效率来源之一。

**TwigVLM++。** v3 的核心变化是 multi-head twig。D-Head 继续做 next-token prediction；P-Head 从最后 twig layer 的 self-attention 相关 query/key 中计算视觉 token importance score $\mathbf{s}$。stage-1 训练整个 twig（含 P-Head）并加入 PredKL 与 AttnKL；stage-2 冻结除 P-Head 外的权重，把 token selection 看作 policy，用 group sampling + reference log-likelihood reward 训练 P-Head；推理时用 P-Head score 替换原 TTP 的 attention map，并用 tree-based SSD 替代 sequence-based SSD。

### 关键公式

VLM 自回归生成定义为：

$$
y_j=\mathop{\text{argmax}}\limits_{\hat{y}_j} p_\mathrm{LLM}(\hat{y}_{j}|\mathbf{X},\mathbf{y}_{<j}),
$$

其中 $\mathbf{X}=[\mathbf{X_v}, \mathbf{X_q}]$，$\mathbf{X_v}=[\mathbf{v}_1,\ldots,\mathbf{v}_M]\in\mathbb{R}^{M\times d}$，$\mathbf{X_q}=[\mathbf{q}_1,\ldots,\mathbf{q}_N]\in\mathbb{R}^{N\times d}$。

Self-attention 与 KV-cache 对应的基本计算是：

$$
\begin{aligned}
&\mathrm{SA}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \mathbf{A}\mathbf{V}=\mathrm{softmax}(\mathcal{M}(\mathbf{Q} \mathbf{K}^T/\sqrt{d})) \mathbf{V}\\
&\mathbf{Q}=\mathbf{X}\mathbf{W_q},\quad\mathbf{K}=\mathbf{X}\mathbf{W_k},\quad \mathbf{V}=\mathbf{X}\mathbf{W_v}.
\end{aligned}
$$

FastV 式 token pruning 函数为：

$$
\begin{aligned}
\mathbf{\hat{X}}^{(K)} &=\mathcal{P}(\mathbf{X}^{(K)}, \mathbf{A}^K, R)\\
&=\left[ \text{TopR}\left(\mathbf{X}_\mathbf{v}^{(K)}, \sum_{i=M+1}^{M+N} \mathbf{A}^{(K)}[i, 1\text{:}M]
\right),\mathbf{X}_\mathbf{q}^{(K)} \right].
\end{aligned}
$$

平均保留视觉 token 数定义为：

$$
\bar{R}=[M\times K + R\times (L-K)]/L.
$$

TwigVLM 的 TTP 改成用最后 twig layer 的 attention：

$$
\mathbf{\hat{X}}^{(K)}_{\mathcal{M}_b} = \mathcal{P}(\mathbf{X}^{(K)}_{\mathcal{M}_b}, \mathbf{A}^{(K+T)}_{\mathcal{M}_s}, R).
$$

FinalWipe 后的平均 token 数为：

$$
\bar{R}=[M\times K + R\times (K_\text{f}-K)]/L.
$$

TwigVLM++ 的 P-Head score 为：

$$
\mathbf{s} = \frac{1}{H}\sum_{h=1}^{H} \sigma\!\left(\frac{\left(\mathbf{G}_q(\mathbf{x_q})^{(h)} \odot \tilde{\mathbf{q}}^{(h)}\right) \left(\mathbf{G}_k(\mathbf{X_k})^{(h)} \odot \tilde{\mathbf{K}}^{(h)}\right)^T}{\sqrt{d_h}}\right),
$$

并替换 pruning signal：

$$
\mathbf{\hat{X}}^{(K)}_{\mathcal{M}_b} = \mathcal{P}(\mathbf{X}^{(K)}_{\mathcal{M}_b}, \mathbf{s}, R).
$$

stage-1 蒸馏损失：

$$
\mathcal{L}_\text{PredKL} = \mathrm{KL}\!\left(p_{\mathcal{M}_b} \,\|\, p_{\mathcal{M}_s}\right),
$$

$$
\mathcal{L}_\text{AttnKL} = \mathrm{KL}\!\left(\mathbf{a}_b \,\|\, \mathbf{s}\right),
$$

$$
\mathcal{L}_\text{stage-1} = \mathcal{L}_\text{NTP} + \alpha \cdot \mathcal{L}_\text{PredKL} + \gamma \cdot \mathcal{L}_\text{AttnKL}.
$$

stage-2 把保留 $R$ 个视觉 token 的动作 $\mathbf{a}=(a_1,\ldots,a_R)$ 写成无放回采样：

$$
\pi_\theta(\mathbf{a}) = \prod_{j=1}^{R} \frac{\pi(a_j)}{\sum_{m \notin \{a_1,\ldots,a_{j-1}\}} \pi(m)}.
$$

reference-based reward 为：

$$
r(\mathbf{a}) = \frac{1}{S}\sum_{j=1}^{S} \log p_{\mathcal{M}_b}(y^*_j \mid \mathbf{\hat{X}}, \mathbf{y}^*_{<j}).
$$

GRPO 风格 group advantage 与 loss 为：

$$
\hat{A}_i = \frac{r_i - \text{mean}(\{r_1,r_2,\ldots,r_G\})}{\text{std}(\{r_1,r_2,\ldots,r_G\})},
$$

$$
\mathcal{L}_\text{stage-2} = \frac{1}{G}\sum_{i=1}^{G} \hat{A}_i \cdot \log \pi_\theta(\mathbf{a}_i).
$$

动态 pruning-ratio schedule 为：

$$
P(\bar{R}\!=\!\bar{R}_i) = \frac{\exp\!\big({-\beta(t) \cdot i}\big)}{\sum_{j=1}^{n} \exp\!\big({-\beta(t) \cdot j}\big)},\quad i=1,2,\ldots,n,
$$

其中 $\beta(t) = \beta_{\max} \cdot ({t}/{T})^{p}$。

### 所用模型 / backbone / 数据流

- Backbone：LLaVA-1.5-7B、LLaVA-NeXT-7B、Qwen2.5-VL-7B；appendix 还给出 LLaVA-1.5-13B。
- 默认 TwigVLM 超参：twig layers $T=3$，pruning position $K=2$，FinalWipe position $K_f=24$。
- TwigVLM++ stage-1：沿用 TwigVLM 训练协议，增加 $\alpha=0.1$ 的 PredKL 与 $\gamma=1.0$ 的 AttnKL。
- TwigVLM++ stage-2：只训练 P-Head；每个 sample 采 $G=32$ 组 pruning actions；候选 $\mathcal{R}=\{64,85,107,128,149,171,192\}$；$\beta_{\max}=8.0,p=2.0$。
- Tree-based SSD：默认 expansion width $\mathcal{E}=10$，selection width $\mathcal{K}=10$，tree depth $\mathcal{D}=4$；appendix 进一步说明保留最多 $N_{\max}=60$ 个候选节点，target model 用 topology-aware causal mask 做 tree attention verification。

**表格解读：Training settings 与 pruning settings。** appendix 的训练表给出 stage-1 使用 AdamW、batch size 128、peak learning rate $1\mathrm{e}{-4}$、665K samples、1 epoch；stage-2 使用 AdamW、peak learning rate $2\mathrm{e}{-5}$、batch size 128、group size 32、50K samples、1 epoch。官方 `twigvlm++` 分支脚本则显示 stage-2 入口实际设为 `learning_rate=1e-4`、`per_device_train_batch_size=1`、`gradient_accumulation_steps=16`、`MAX_STEPS=500`，若用 8 卡运行有效 batch size 同样是 128，但 learning rate 与论文表格不一致（已据代码核对修订）。pruning settings 表给出在 LLaVA-1.5-7B 默认 $K=2,K_f=24$ 下，$\bar{R}=192/128/64$ 分别对应 $R=227/134/41$。这些表说明 aggressive pruning 的“平均只保留 64 个 token”并不等于第 2 层只留 64 个，而是依靠 FinalWipe 允许中间层保留更多视觉 token。

### 算力资源需求

论文明确写明所有训练在 8 NVIDIA A100 GPUs 的服务器上进行。对于 LLaVA-1.5-7B，TwigVLM 训练约 10 GPU-hours，约为原始 LLaVA-1.5-7B 训练时间的 10%；TwigVLM++ 训练约为原始训练时间的 20%，据同一口径估算约 20 GPU-hours。这里的 “GPU-hours” 按论文文字理解为总 GPU 小时；若按 8 卡 wall-clock 折算，10 GPU-hours 约等于 8 卡同时运行约 1.25 小时，20 GPU-hours 约等于 2.5 小时。

对 Qwen2.5-VL-7B，main text 说使用 MAmmoTH-VL-10M 的 5M single-image samples；appendix 注释里曾写过 8*A100 训练约 12 小时（该段在 TeX 中被注释掉），因此只能作为估算线索。保守写法是：Qwen2.5-VL 的训练计算量显著高于 LLaVA-665K，因为样本数从 665K 增到 5M；若按注释的 8 卡 12 小时计算，则约为 96 GPU-hours，但这不是正式正文结果，需标注为估算。

推理显存方面，appendix 的 memory footprint 表显示 twig block 带来约 8% 额外 model weights VRAM：LLaVA-1.5-7B 从 14.3GB 到 15.5GB，inference VRAM 从 15.8GB 到 16.5GB；LLaVA-NeXT-7B 从 14.3GB 到 15.5GB，但因视觉 token 大幅减少，inference VRAM 从 17.9GB 降到 16.8GB。说明额外权重开销存在，但在高分辨率/多 token 模型上可能被 token reduction 抵消。

## 9. 实验

### 9.1 评测数据集

主实验使用三类模型和多组 benchmark：

- LLaVA-1.5-7B / LLaVA-NeXT-7B：GQA、MMBench、MME、TextVQA、ScienceQA-Image、VQA-v2。
- Qwen2.5-VL-7B：图像 benchmark 包括 GQA、MME、MMBench、ScienceQA-Image、TextVQA、VQA-v2、MMStar、OCRBench、BLINK；视频 benchmark 包括 Video-MME、EgoSchema、MVBench。
- 速度评测：TextVQA 代表短回答，平均生成 token 数 $\bar{S}=4$；MM-Vet 代表长回答，平均生成 token 数 $\bar{S}=72$。
- appendix 补充：LLaVA-1.5-13B；LLaVA-1.5-7B 上扩展到 POPE、MMMU、MM-Vet；数据效率实验使用 LLaVA-665K 与 MAmmoTH-VL-10M 的不同比例。

### 9.2 评测指标

- Relative Accuracy (RelAcc)：pruned/accelerated model 的 accuracy 除以 base model accuracy；多个 benchmark 时分别算相对准确率再平均。
- Relative Speed (RelSpd)：生成 token 数除以总生成时间（包含 prefilling 与 decoding），再相对 base model 的 generation speed 归一化。
- Token Acceptance Rate (TokAR)：draft token 被 target model 接受的比例，用于解释 SSD 速度。
- 具体 benchmark 的分数沿用各自标准：如 MME 为 perception + cognition 汇总分，MMBench 为层级选择题评估，TextVQA/OCRBench 关注图中文字理解，Video-MME/EgoSchema/MVBench 关注视频理解与时序推理。

| 128 | 77.8% | 92.2% | 96.1% | 98.7% | 99.2% |
| 64 | 88.9% | 77.0% | 93.3% | 96.0% | 97.7% |

**LLaVA-NeXT-7B。** 表 2 的视觉 token 上限为 2880，测试 77.8% 与 88.9% pruning。$\bar{R}=640$ 时 TwigVLM 与 TwigVLM++ 都达到 99.0% RelAcc；$\bar{R}=320$ 时 TwigVLM++ 97.1%，优于 TwigVLM 96.2%、VisionZip 93.8%、VisionZip‡ 95.8%、FastV 88.2%。这说明在更长视觉序列的 LLaVA-NeXT 上，TwigVLM++ 仍能保持准确率，但 TextVQA 单项不一定最好，论文的优势主要体现为综合 RelAcc。

### 9.4 消融实验

**TwigVLM 消融。** 表 4 证明原始 TwigVLM 的各组件都在起作用：

- attention source：第 $K$ 层 backbone attention 只有 82.3% RelAcc；第 $K+T$ 层 backbone attention 为 86.2%；最后 twig layer attention 达 96.0%。这说明“层深”与“离 prediction head 的距离”都影响 pruning signal。
- acceleration strategy：FastV 式 token pruning 只有 104.3% RelSpd；SSD-only 为 146.7%；TTP+SSD 达 153.6%。速度主要来自 decoding SSD，TTP 是补充收益。
- initialization：random init 为 87.2% / 120.4%；用 base VLM 最后 $T$ 层初始化为 90.4% / 131.4%；用 $K$ 到 $K+T$ 层初始化达 96.0% / 153.6%。
- twig depth：$T=1$ 速度最高 154.1% 但准确率 93.9%；$T=3$ 准确率最高 96.0% 且速度 153.6%；$T=4$ TokAR 继续升但速度降到 145.4%，因为 draft 计算成本抵消了接受率收益。
- pruning position 与 FinalWipe：$K=2,R=41,K_f=24$ 是默认最佳组合；不使用 FinalWipe 时 $\bar{R}=64$ 对应 $R=30$，准确率只有 93.1%，加入 FinalWipe 后可在中间层保留更多 token，准确率到 96.0%。

图解：表 4 是原始 TwigVLM 的机制拆解表。它最重要的信息不是某个单点数字，而是说明 TwigVLM 的准确率来自 twig-guided selection，速度来自 SSD，FinalWipe 则通过改变 token budget 分布改善 aggressive pruning 下的准确率。

**TwigVLM++ 消融。** 表 5 显示 v3 增量的贡献：

- stage-1 架构与 loss：D-Head + NTP baseline 为 96.0%；加入 P-Head 与 AttnKL 后 stage-1 反降到 95.0%，但经过 stage-2 到 97.2%；再加入 PredKL 后 stage-1 为 96.4%，stage-2 为 97.7%。这说明 P-Head 需要 distillation 才能避免分裂训练能力。
- pruning-ratio strategy：static $\bar{R}=64$ 在 $\bar{R}=64$ 测试点最高 98.0%，但在较大保留率退化；dynamic schedule 在 $\bar{R}=192$ 最好，整体更均衡。
- stage-2 data scale：10K 到 20K 提升明显，20K 到 50K 增益很小，100K 无进一步提升；作者选择 50K 作为稳定默认。

图解：表 5 支撑“multi-head 本身不够，必须配合 PredKL 与 RL”的判断。尤其是 P-Head+AttnKL 在 stage-1 的下降提醒读者：新增结构会带来 optimization burden，后续 RL 才是把 P-Head 变成 pruning head 的关键。

**appendix 额外消融。** TokAR 表显示 $K:K+T$ 初始化把 TokAR 提到 57.4%，对应最高 153.6% RelSpd；$T=4$ 的 TokAR 最高 58.1%，但 RelSpd 降到 145.4%，说明 draft model 不是越强越好。memory footprint 表显示 twig block 增加约 8% model-weight VRAM，但 LLaVA-NeXT 因 token 大幅减少，整体 inference VRAM 反而下降。

### 9.5 结果分析

**作者认为。** 作者认为 TwigVLM 的核心优势是一个统一框架同时处理 prefilling 与 decoding：TTP 用更准确的 twig signal 保留关键视觉 token，SSD 用浅模型 draft 减少串行 decoding 步数。v3 的 TwigVLM++ 进一步说明原始 twig 的 pruning 能力没有直接优化，因此 P-Head/D-Head 解耦、PredKL/AttnKL、pruning-oriented RL 和 tree-based SSD 分别改善 pruning quality 与 generation speed。作者还强调，TwigVLM++ 在 Qwen2.5-VL 上的增益更明显，说明多头与 RL 对强 base VLM 更有价值。

**agent 分析。** 我认为这篇论文的位置可以概括为“训练式 visual token pruning 与 self-speculative decoding 的 VLM 化拼接，但拼接得很实用”。它不是从零发明 pruning，也不是从零发明 speculative decoding；真正的价值在于识别了两者分别覆盖 prefilling / decoding，并用共享低层 twig 把两段工程成本压低。v3 的 P-Head/RL 更像把 v1 中“偶然可用的 attention”变成“直接面向 pruning reward 的 policy”，这是方法上更扎实的部分。

同时，论文的强结论依赖几个条件。第一，长回答越多，SSD/tree SSD 的优势越大；短回答 benchmark 上速度差距并不夸张。第二，TwigVLM++ 需要额外训练与额外权重，不是 FastV/VisionZip 那种 zero-training 插件。第三，RL reward 是 reference likelihood，虽然高效，但不是严格任务 reward；对开放式视觉问答、带多正确答案的问题，reference log-prob 与人类评判之间可能有偏差。第四，`VisionZip‡` 未定义会影响读者判断 strongest baseline 的设置，建议后续代码分析或复现实验时重点核对。

![Figure 9: more attention map visualizations](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig9.pdf)

图解：图 9 补充 16 个 GQA/TextVQA 例子的 attention map 与预测。作者用它说明 TwigVLM 的错误有时不是 pruning 造成的，因为 heatmap 已经落在合理区域但 base VLM 仍可能答错。这一点对批判很重要：token selection 只能减少视觉信息损失，不能修复 base VLM 的识别、OCR 或推理能力上限。

![Figure 10: SSD accepted tokens](sources/2503.14075-twigvlm-plus-plus/arxiv/figures/fig10.pdf)

图解：图 10 用 MM-Vet 长回答例子展示 SSD 中 target model 接受的 token（绿色）。大量语法词、常见描述词会被接受，而更难的语义或推理片段更可能由 target 修正。它解释了为什么 TwigVLM 在长文本生成中有效：自然语言回答里有足够多“容易预测”的 token，可由 shallow draft 批量提出。

### 10.2 方法实现核对

**与论文一致。**

- multi-head twig / P-Head / D-Head 解耦确实落在代码里。P-Head 名为 `Pruning_Head` / `leaf_attention_module`，定义在 `twigvlm/model/language_model/llama/pruning_head.py:7`，训练模型通过 `build_leaf_attention_module()` 创建它（`modeling_llama_twig++_stage1.py:1173-1175`、`modeling_llama_twig++_stage2.py:1193-1195`）。D-Head 不是另写一个叫 `DHead` 的类，而是 twig 路径上的 `lm_head`；推理加载时会把 checkpoint 的 `lm_head.weight` 映射到 `model.twig_head.weight`（`twigvlm/inference/builder.py:125-135`）。
- P-Head 公式与论文方向一致：代码用 question token 的 Q、image tokens 的 K、以及 hidden state 经过 `q_gate/k_gate` 后的门控项相乘，做 $\sqrt{d_h}$ 缩放 softmax，再跨 head 求平均。关键片段如下。

```python
# twigvlm/model/language_model/llama/pruning_head.py:31-42
X1 = self.q_gate(X).view(self.n_heads, 1, self.d_head)
Y1 = self.k_gate(Y).view(-1, self.n_heads, self.d_head).transpose(0, 1)
Q = Q.view(self.n_heads, 1, self.d_head) * self.act(X1)
K = K.view(self.n_heads, -1, self.d_head) * self.act(Y1)
logits = torch.matmul(Q, K.permute(0, 2, 1)).squeeze(1).to(torch.float32) / math.sqrt(self.d_head)
return F.softmax(logits, dim=-1).mean(dim=0)
```

- stage-1 distillation 的三个损失都能在实现中找到。`modeling_llama_twig++_stage1.py:1242-1245` 从环境变量读取 `D_ALPHG`、`D_TEMP`、`A_GAMMA`、`A_B`；`1247-1265` 用 frozen base path 取 teacher hidden / QK；`1307-1318` 实现 PredKL；`1350-1383` 用 teacher deep-layer attention 和 P-Head score 做 AttnKL；`1390-1409` 汇总为 NTP + $\gamma$ AttnKL + $\alpha$ PredKL。训练脚本默认 `D_ALPHG=0.1`、`D_TEMP=5.0`、`A_GAMMA=1.0`、`A_B=19`，与 README 给出的 stage-1 超参一致。
- stage-2 确实只更新 P-Head。`twigvlm/train/train_stage2.py:966-971` 先 `model.requires_grad_(False)`，然后只把名字含 `leaf` 的参数设为 `requires_grad=True`；`973-988` 从 stage1 checkpoint 加载 twig layers、norm、lm_head 与 leaf head。
- stage-2 的采样和 advantage 也与论文主线一致：代码用 P-Head 分布无放回采样多组视觉 token，base VLM 对剪枝后的序列计算 reference answer 的 token CE，再按 group 做标准化 advantage。注意代码内部用的是第 2 层实际保留数 `[41,72,103,134,165,196,227]`，对应论文平均保留数 $\bar{R}=\{64,85,107,128,149,171,192\}$。

```python
# twigvlm/model/language_model/llama/modeling_llama_twig++_stage2.py:1385-1390,1422-1429,1443-1448
num_samples = sample_smooth_left_shift(self.step_id, max_steps*16, power=power)
sampled_indices = torch.multinomial(s_probs_expanded, num_samples, replacement=False)
neg_reward = loss_fct(logits_, labels_).view(num_groups, seq_len).mean(dim=-1)
neg_advantage = (neg_reward - neg_reward.mean(dim=-1, keepdim=True)) / (neg_reward.std(dim=-1, keepdim=True) + 1e-6)
action_prob_logits = s_probs_expanded[...].float().log().squeeze(-1).sum(dim=-1)
grpo_loss = (action_prob_logits * neg_advantage).mean()
```

- TTP / FinalWipe 推理流程在代码里落地。`twigvlm/inference/twigvlm_patcher.py:94-103` 根据用户传入的平均保留 token 数换算第 2 层实际保留数；`ssd_generator_with_ttp.py:111-130` 在最后一个 twig layer 取 QK，经 `PHead_attention_module` 打分并 top-k；`forward_remainder()` 在 target model 的 `wipe_layer=[2,24]` 处执行第一次保留与 FinalWipe（`ssd_generator_with_ttp.py:228-247`）。
- tree-based SSD 也确实实现了 tree attention verification：`ssd_generator_with_ttp.py:410-411` 硬编码 `top_k=10`、`total_tokens=60`，`440-495` 构造候选 token tree、parent mask、`tree_position_ids`，`534-547` 一次送入 target model 校验；`utils.py:161-188` 把 `tree_mask` 写进 causal attention mask。

**与论文 / 报告表述存在差异。**

- stage-2 learning rate：论文 appendix / 原报告表述为 peak LR $2\mathrm{e}{-5}$，但官方脚本 `scripts/v1_5/train/train_twig++_stage2.sh:48` 实际是 `--learning_rate 1e-4`。这不是估算误差，而是公开脚本与论文表格的直接差异。
- stage-2 loss 并非纯 GRPO/RL。`modeling_llama_twig++_stage2.py:1451-1471` 在 GRPO loss 后继续计算 teacher attention KL，并以随 `num_samples` 线性变化的 `gamma` 叠加到 loss 上；论文主线把 stage-2 描述为 pruning-oriented RL，未突出这个 AttnKL regularizer。
- README 写 stage2 只需约 50K samples；脚本在 8 卡时 `per_device_train_batch_size=1`、`gradient_accumulation_steps=16`、`MAX_STEPS=500`，按 optimizer step 粗算会消耗约 $8\times1\times16\times500=64K$ sample exposures。若按 README 的“至少 4 GPU”运行，则又是约 32K exposures。因此“50K”更像近似口径，而不是脚本可唯一推出的精确样本数。
- CLI demo 的参数默认值有小坑：`cli_demo.py:27` 里 `--R` 默认是 `3`，但 README demo 用 `--R 64`。按代码换算公式，`R=3` 会得到异常小的第一阶段保留数，不应视为论文默认设置。
- 当前仓库没有找到 Qwen2.5-VL / LLaVA-NeXT 对应的代码路径，因此表 2/3 的训练细节与评测脚本无法只靠该开源仓库完整验证。

**论文未强调但代码中存在的工程细节。**

- PredKL 有额外 clipping / normalization：`modeling_llama_twig++_stage1.py:1315-1318` 用 `CLIP=4.0` 对 token-level KL 做上限缩放，并除以 `CLIP` 后再平均；论文公式没有写这个稳定化处理。
- 训练强制使用 FlashAttention2：`train_stage1.py:829-832` 和 `train_stage2.py:830-832` 加载 base model 时指定 `attn_implementation='flash_attention_2'`。但 README 明确说 tree-based speculative decoding 推理不能用 FlashAttention2，demo / eval 均用 eager（如 `cli_demo.py:48-54`、`model_vqa_loader.py:92`）。
- 推理只可靠覆盖 greedy/argmax 路径。评测脚本默认 `temperature 0`；`utils.py:50-54` 在 `sample=True` 时直接 `raise NotImplementedError("Sampling is not implemented yet.")`，tree SSD 验证时也用 `torch.argmax` 选择 target token（`ssd_generator_with_ttp.py:565-589`）。
- 自定义 `image_tags` 是 TTP/RL 能工作的重要工程约定。`llava_arch.py:245-315` 将视觉 token 标成正数、不同文本区域标成负数，P-Head 再用 `-3` 位置作为 query token、`1` 作为 image token mask（`utils.py:201-216`）。论文不会写到这个级别，但复现时 tag 规则错了会直接破坏 P-Head 打分。
- 评测脚本是多进程按 GPU 分 chunk 跑，而不是 batch 推理。`scripts/v1_5/eval/gqa.sh:30-42` 根据 `CUDA_VISIBLE_DEVICES` 拆分问题，每张 GPU 跑一个 Python 进程，最后合并 jsonl。

### 10.3 真实算力规模

- README 的硬件声明：训练至少 4 张显存超过 40GB 的 GPU，示例为 8×NVIDIA A100；推理 / 评测单张显存超过 40GB 的 GPU 即可。
- stage-1 入口：`scripts/v1_5/train/train_twig++_stage1.sh` 使用 Deepspeed ZeRO-2、bf16、tf32、FlashAttention2、`model_max_length=2048`、`num_train_epochs=1`、`per_device_train_batch_size=4`、`gradient_accumulation_steps=4`、`learning_rate=1e-4`、`warmup_ratio=0.03`、cosine scheduler、`gradient_checkpointing=False`。若按 8 卡运行，有效 batch size 为 $8\times4\times4=128$。
- stage-2 入口：`scripts/v1_5/train/train_twig++_stage2.sh` 使用 Deepspeed ZeRO-2、bf16、tf32、FlashAttention2、`model_max_length=2048`、`per_device_train_batch_size=1`、`gradient_accumulation_steps=16`、`MAX_STEPS=500`、`learning_rate=1e-4`、`warmup_ratio=0.01`、cosine scheduler、`NUM_GROUPS=32`、`POWER=2.0`。若按 8 卡运行，有效 batch size 仍为 128，但每个样本内部还会展开 32 组 pruning action 并多次跑 base VLM 评分，因此实际计算压力高于普通 128 batch 的 SFT。
- 依赖层面没有看到 H100 专属算子；硬要求主要来自 LLaVA-1.5-7B + FlashAttention2 + Deepspeed + 40GB 级显存。推理阶段由于 tree mask 需要 eager attention，速度结果高度依赖 eager attention 实现、单样本长生成和 KV cache 裁剪效率。
- 与第 8 节算力估算对照：论文“8×A100、TwigVLM 约 10 GPU-hours、TwigVLM++ 约 20 GPU-hours”的宏观说法与 README 推荐硬件不冲突；代码补充了有效 batch size、bf16/tf32、ZeRO-2、max length、warmup 和 scheduler。但 stage-2 LR 与论文表格不同，且 50K samples 的口径与脚本按 8 卡折算的 64K exposures 不完全一致。

### 10.4 可复现性评价

- 综合评价：中偏低。仓库给出了核心训练 / 推理代码、Apache-2.0 license、stage1/stage2 权重下载入口和 demo，单图 LLaVA-1.5 推理应该可按 README 跑通；但完整复现论文所有表格需要较多手工修路径、下载外部数据，并补齐 Qwen2.5-VL / LLaVA-NeXT 路径。
- 主要可复现障碍：训练脚本中的 `DATA_PATH="{dir}/..."`、`IMAGE_FOLDER="{dir}/..."` 必须手改；多个 eval 脚本仍保留 `{path-dir}` 占位符，`textvqa.sh` / `vqav2.sh` 还含作者集群的 `/mnt/pfs...` 绝对路径；多数 eval 脚本默认 `CKPT="TwigVLM-llava-v1.5-7b-K2-T3"`，不是 README 所说的 `TwigVLM++-stage2-llava1.5-7b-K2-T3`。
- 数据与日志：仓库不随附 LLaVA-665K 图片、benchmark 数据或 reproduction log；代码会打印训练时间和 peak reserved memory（`train_stage1.py:993-1003`、`train_stage2.py:1002-1012`），但没有官方日志文件或 deterministic seed 设置。训练结果会受数据顺序、distributed sampler 和随机 pruning action 采样影响。
- 对普通研究者的建议：若目标是验证方法实现，优先下载 README 的 stage2 权重，在单张 40GB+ GPU 上跑 `cli_demo.py` 或一个小型 eval；若目标是完整重训，需要 4-8 张 A100 级 GPU、可用的 LLaVA-665K 本地数据、可编译 FlashAttention2 的 CUDA 环境，并手动清理 eval 脚本里的占位符和内部路径。
