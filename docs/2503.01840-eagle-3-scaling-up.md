# EAGLE-3：通过训练时测试扩展大语言模型推理加速

## 1. 基本情况

- **题目**：EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test
- **作者**：Yuhui Li（北京大学 / 滑铁卢大学）、Fangyun Wei（微软研究院）、Chao Zhang（北京大学）、Hongyang Zhang（滑铁卢大学 / Vector Institute）
- **单位**：北京大学、Microsoft Research、University of Waterloo、Vector Institute
- **arxiv 编号**：2503.01840；提交日期 2025-03-03
- **arxiv 链接**：https://arxiv.org/abs/2503.01840v3
- **代码仓库**：https://github.com/SafeAILab/EAGLE

## 2. 核心贡献概述

**中文版**：EAGLE-3 发现了 EAGLE 系列 draft model 在扩大训练数据时收益有限的根因——feature prediction loss 构成了不必要的表达力约束，并提出两项关键改进：(1) 去掉 feature prediction constraint，改用 direct token prediction，配合训练时模拟多步生成的 training-time test 技术；(2) 将 target model 的 top-layer feature 替换为 low/mid/high 三层 feature fusion。由此 EAGLE-3 的 draft model 首次展现出推理加速领域的 scaling law——训练数据越多，speedup 越高。

**英文版**（摘自 Abstract）："We introduce EAGLE-3, which abandons feature prediction in favor of direct token prediction and replaces reliance on top-layer features with multi-layer feature fusion via a technique named training-time test. These improvements significantly enhance performance and enable the draft model to fully benefit from scaling up training data."

## 3. 一句话精髓（写给外行）

给大模型装一个更聪明的"打草稿"助手：过去的助手被要求照抄上级的笔记（feature prediction），反而学不好；现在让它自由发挥、同时在训练时就模拟真实的打草稿过程，它就能随着练习量的增长越来越快——就像一个实习生，不再被条条框框束缚后，终于能从大量实践中真正成长起来。

## 4. 学术贡献清单

### 4.1 动机的发现与阐明

论文揭示了一个此前未被系统讨论的现象：**EAGLE 的 draft model 在扩大训练数据时几乎无法获益**。作者从 LLaMA 系列的 scaling 实践（1T→2T→15T tokens）出发，类比推理地试图用更多数据训练 EAGLE 的 draft model，却观察到 acceptance rate 几乎不再提升。

根因分析分两层：

1. **Feature prediction loss $l_{\text{fea}}$ 是一个额外约束**：EAGLE 的 loss 包含 feature prediction loss 和 token prediction loss 两部分。虽然 $l_{\text{fea}}$ 让 draft model 在仅训练 Step 1 的情况下也能适应 Step 2，但它本质上要求 draft model 的输出去拟合 target model 的 top-layer feature——这不是最终目标（token prediction），而是一个限制表达力的附加约束。

2. **Top-layer feature 天然只编码 next-token 信息**：对于 full-rank LM head，top-layer feature 与 next-token logit 之间存在一一对应关系，这些 feature 本身就被"锁定"在 next-token 预测的信息上，用它来预测 next-next token 信息不足。

论文通过逐步实验验证了这个分析链：去掉 $l_{\text{fea}}$ 后 $0$-$\alpha$ 显著提升，但 $1$-$\alpha$ 骤降（因为 draft model 输出偏离训练分布）；再加入 training-time test 后两者同时改善。

### 4.2 方法的创新

1. **去掉 feature prediction，改用 direct token prediction**：不再要求 draft model 输出拟合 target model 的 top-layer feature，解除了输入端的约束。

2. **Multi-layer feature fusion**：将 target model 的 low/mid/high-level feature concatenate 成 $3k$-dim 向量，再通过 FC 层降维到 $k$-dim，获得融合多层语义信息的特征 $g$。

3. **Training-time test**：在训练阶段模拟推理时的多步生成过程——将 draft model 自身的输出 $a$ 反馈回输入，配合特殊的 attention mask（见 Figure 3），让 draft model 学会处理自己的估计值而非 target model 的精确值。

4. **与 EAGLE-2 的 dynamic draft tree 完全兼容**：EAGLE-3 继承了 EAGLE-2 的上下文感知动态树结构，进一步提升了效率。

### 4.3 实验上的核心结论

- EAGLE-3 在所有任务和所有 target model 上均取得最高 speedup ratio 和 average acceptance length，最高达 **6.5x** 加速（HumanEval, Vicuna 13B, temp=0）。
- 相比 EAGLE-2，EAGLE-3 提升约 **20%-40%** 的加速比。
- 在 SGLang 生产级框架中，EAGLE-3 在 batch size=64 时仍能带来 **38% 吞吐提升**（而 EAGLE 在 bs=24 时已开始降低吞吐）。
- EAGLE-3 展现出**推理加速领域的 scaling law**：训练数据量与 speedup ratio 之间呈正相关，这一规律在 EAGLE 架构中不存在。

## 5. 写作故事线

论文的叙事链条可以概括为 **"发现问题→定位根因→逐步拆解→验证 scaling"**。

**第一幕（Introduction 前半）：设定背景。** 从 LLM 推理成本高昂出发，引入 reasoning models（ChatGPT o1、DeepSeek-R1）的长推理链问题，说明 speculative decoding 的需求比以往更迫切。接着介绍 EAGLE 系列的核心思路——在 feature level 做 autoregression 并复用 target model 的 top-layer feature。

**第二幕（Introduction 中段）：揭示 scaling wall。** 作者发现了一个反直觉的现象：增加训练数据对 EAGLE 的 draft model 几乎没有帮助。这与 LLM pre-training 的 scaling law 形成鲜明对比。论文用 Figure 5（`fig:nofe`）作为核心诊断工具，将问题拆解为两个子问题：(1) feature prediction loss 的约束；(2) draft model 输出偏离训练分布导致的 error accumulation。

**第三幕（Introduction 后段 + §3）：提出解决方案。** 每解决一个子问题，就做一个消融验证。去掉 $l_{\text{fea}}$ 后 $0$-$\alpha$ 提升但 $1$-$\alpha$ 下降；加入 training-time test 后两者同时改善。接着从 top-layer feature 的信息瓶颈出发，引入 multi-layer feature fusion。最后给出完整的 EAGLE-3 推理 pipeline（Figure 1）和训练流程（Figure 3）。

**第四幕（§4 Experiments）：全面验证。** 在 4 个 target model（Vicuna 13B、LLaMA 3.1 8B、LLaMA 3.3 70B、DeepSeek-R1-Distill 8B）× 5 个任务 × 2 个温度设置上做全面对比。通过 acceptance rate 曲线（Figure 4）证明 training-time test 消除了 error accumulation。通过 scaling curve（Figure 2）证明新架构首次在推理加速领域展现出 scaling law。在 SGLang 和 vLLM 生产级框架上验证大 batch 吞吐。

**关键转折点**：Figure 5 的三步对比图是全文叙事的核心——它把一个模糊的 "EAGLE 不 scaling" 现象分解成了两个可操作的子问题，每个子问题对应一个改进，最终收敛到 EAGLE-3 的设计。

## 6. 核心参考文献

1. **[22] Li et al. 2024 — EAGLE**：EAGLE 系列的开山之作，提出在 feature level 做 autoregression 并复用 target model top-layer feature 的核心思路。EAGLE-3 的所有改进都建立在对 EAGLE 局限性的诊断之上。

2. **[23] Li et al. 2024 — EAGLE-2**：引入 context-aware dynamic draft tree，EAGLE-3 完全继承了这一技术。也是 EAGLE-3 的主要 baseline。

3. **[7] Cai et al. 2024 — Medusa**：另一种复用 target model feature 的方法（添加多个 decoding heads），与 EAGLE 同属 feature-reuse 家族。论文通过对比 Medusa 来论证 feature prediction constraint 的问题。

4. **[21] Leviathan et al. 2023 / [2] Chen et al. 2023 — Speculative Sampling**：speculative decoding 的理论基础，定义了 drafting + verification 的无损加速框架。EAGLE-3 遵循该框架保证输出分布一致性。

5. **Zhang et al. 2024 — HASS**：与 EAGLE-3 在训练时模拟多步生成的 attention mask 修改上高度重叠，但动机和结果不同。论文用大段篇幅区分两者：HASS 仍保留 feature prediction loss，而 EAGLE-3 去掉了它。

6. **[19] Dubey et al. 2024 — LLaMA 3**：LLaMA 系列 scaling 实践的代表，从 1T→15T tokens 的数据增长为 EAGLE-3 的 scaling 动机提供了类比基础。

7. **[1] Guo et al. 2025 — DeepSeek-R1**：reasoning model 的代表，其长推理链导致极高的推理成本，是本文强调 speculative decoding 迫切性的现实背景。

8. **[10] Zheng et al. 2024 — SGLang**：生产级 LLM 推理框架，EAGLE-3 的吞吐实验在该框架上进行，验证了大 batch 场景下的实际收益。

## 7. 批判性分析

### 7.1 与 HASS 的高度重叠

论文 §3.2 自己承认 "HASS and EAGLE-3 both make similar modifications to the attention mechanism to simulate the testing process during training"，并用大段文字区分动机。但技术层面，两者在训练时模拟多步生成的 attention mask 修改（Figure 3）本质上是同一操作。EAGLE-3 的真正差异化在于**去掉** $l_{\text{fea}}$ 后使得输入可以不再是 top-layer feature——这是一个减法式改动，而非新增机制。论文对 HASS 的批评（"HASS still performs feature prediction, includes a feature prediction loss $l_{\text{fea}}$"）虽然成立，但并未提供 HASS 在相同数据量下的对比实验来量化这一差异的实际影响。

### 7.2 Multi-layer feature fusion 的工程复杂度被高估

论文将 "融合 low/mid/high-level features" 作为核心贡献之一，但实现上仅是三个 $k$-dim 向量 concatenate 成 $3k$-dim 再过一个 FC 层降回 $k$-dim（§3.1）。这是一个标准的线性投影操作，不涉及注意力机制、cross-attention 或自适应权重。论文未做消融对比不同层选择策略（如只用两层、用更多层、用可学习层选择），也未分析不同 target model 深度下哪几层最有价值。

### 7.3 "Scaling law for inference acceleration" 的证据局限

Figure 2（`fig:sc`）的 scaling curve 仅在 LLaMA-Instruct 3.1 8B + MT-bench 上展示。论文未验证该 scaling behavior 在不同模型族（如 Qwen、Mistral）、不同规模（70B+）、不同任务类型上是否成立。将其命名为 "discovery of a scaling law" 并作为三大贡献之一，证据覆盖面不足。此外，x 轴是 "data scale relative to ShareGPT"，而 ShareGPT 仅约 68K 条目，scaling range 有限。

### 7.4 架构改进与数据量提升的贡献未解耦

论文声称 EAGLE-3 "trained with approximately 8x more data than EAGLE, achieves a 1.4x latency speedup over EAGLE-2"。消融实验（Table 2）显示 "remove fea con" 贡献了 3.16x→3.82x（+21%），"fused features" 再贡献 3.82x→4.40x（+15%）。但论文未做**相同数据量下** EAGLE-2 vs EAGLE-3 的公平对比，无法分离架构改进和数据量提升各自的贡献。从消融实验的设置看（仅用 LLaMA 3.1 8B + MT-bench/GSM8K），"fused features" 的额外收益（+15%）相对于 "remove fea con"（+21%）并不突出，multi-layer fusion 的独立价值存疑。

### 7.5 消融实验覆盖不足

消融实验仅在 LLaMA-Instruct 3.1 8B + MT-bench/GSM8K 上进行。未在 70B 模型或 DeepSeek-R1-Distill 上验证两个改进各自的贡献比例是否一致。更关键的是，消融没有覆盖 training-time test 的模拟步数——Figure 3 展示了 3 步（1 原始 + 2 模拟），但论文未讨论步数选择的影响，这是训练流程中最关键的超参之一。

### 7.6 Draft model 极简结构未充分讨论

§3.2 写道 "The core of the draft model in EAGLE-3 is a Transformer decoder layer"。整个 draft model 仅含：FC 层做 feature 融合 + FC 层做 embedding 拼接 + 单层 decoder + target model 的 LM head。论文未讨论为什么单层就足够、增加层数是否还有收益、以及这个极简结构是否限制了在更难任务上的表现。考虑到 EAGLE-3 声称的 scaling law，draft model 容量是否也应随数据量增长而扩大，是一个自然的后续问题。

### 7.7 吞吐实验配置不一致

SGLang 和 vLLM 吞吐实验由第三方执行，且与主实验的 decoding 策略不同：
- 主实验（Table 1）：tree structure + depth 8 + expansion nodes 10
- SGLang 实验（Table 3/4）：chain-only, chain length=3
- vLLM 实验（Table 5）：chain-only, max chain length=2

这意味着 speedup 数据和吞吐数据在不同 decoding 策略下测得。Table 3 中 chain-only 的 EAGLE-3 在 bs=2 时是 1.81x，而 Table 1 中 tree-based 的 EAGLE-3 在 MT-bench 上是 4.40x（LLaMA 3.1 8B, temp=0）——差距巨大，说明 tree structure 贡献了相当大一部分 speedup。此外，vLLM 实验正文写 "results on RTX3090"，但 Table 5 caption 写 "A100"，存在矛盾或笔误。

### 7.8 未与最强同期方法充分对比

BibTeX 中引用了 Sequoia（动态规划最优树结构）、Kangaroo（double early exiting）等方法，但 Table 1 的对比方法仅包括 SpS、PLD、Medusa、Lookahead、Hydra、EAGLE、EAGLE-2、HASS。对于声称 "up to 6.5x speedup" 的论文，未与最强同期方法对比是明显的覆盖不足。

### 7.9 训练数据选择缺乏消融

论文用 ShareGPT（~68K 条）+ UltraChat-200K（~464K 条）训练，推理模型额外加 OpenThoughts-114k-math。但未讨论：为什么选 UltraChat 而非其他大规模对话数据集？数据质量 vs 数据数量各自贡献多少？对于 reasoning model，OpenThoughts-114k-math 的 domain-specific 数据是否是 GSM8K 上高加速比的主要原因（论文自己也暗示了这点，§4："This may be because we trained the draft model of DeepSeek-R1-Distill-LLaMA 8B using the OpenThoughts-114k-math dataset"）？如果 task-specific 训练数据是关键因素，那 "scaling law" 可能更多是数据分布匹配的 artifact。

### 7.10 DeepSeek-v3 双向启发叙事缺乏实质支撑

§3.2 写 "EAGLE inspired the multi-token prediction technique used in the pre-training of DeepSeek-v3, which in turn inspired new architectural designs in EAGLE-3"。这暗示了一个学术上的双向影响闭环，但论文没有引用 DeepSeek-v3 的具体章节或实验来证明 EAGLE 确实启发了其 multi-token prediction 设计，也没有说明 EAGLE-3 的哪些具体设计细节来自 DeepSeek-v3 的启发。这段叙事更像是定位声明而非有据可查的学术关联。

### 7.11 复现风险：关键超参缺失

EAGLE-3 的完整复现需要：(a) FC 层维度配置（§3.1 提到 $3k \to k$，但 low/mid/high 各层的具体 layer index 未给出）；(b) draft tree depth=8、expansion nodes=10（Appendix）；(c) 训练超参（AdamW, lr=5e-5, $\beta=(0.9, 0.95)$, gradient clipping=0.5）；(d) training-time test 的模拟步数（Figure 3 画了 3 步，但未写明这是默认设置还是示例）。其中 (a) 的具体 layer 选择是最关键的缺失——论文只说 "low, middle, and high-level"，没有给出 target model 中具体是第几层。

## 8. 方法细节

### 8.1 算法流程

EAGLE-3 的推理流程交替进行 **drafting** 和 **verification** 两个阶段，与标准 speculative sampling 一致。差异在于 drafting 阶段的实现。

**Drafting 阶段**（以 Figure 1 为例，prefix = "How can"）：

1. **Feature 融合**：target model 前一次 forward pass 产生 low-level feature $l$、mid-level feature $m$、high-level feature $h$（各 $k$-dim）。将三者 concatenate 成 $3k$-dim 向量，通过 FC 层降维到 $k$-dim，得到融合特征 $g$。

2. **Embedding 拼接**：为了捕获 sampling 的随机性，将上一步 sampled token 的 embedding $e$ 与 $g$ 拼接（$2k$-dim），再通过 FC 层降维到 $k$-dim。

3. **单层 Decoder**：将处理后的向量输入单层 Transformer decoder，产生输出 $a$。

4. **LM Head 采样**：将 $a$ 输入 target model 的 LM head，采样得到 draft token。

**多步生成**：
- Step 1：输入来自 target model 的 $g_{\text{how}}$, $g_{\text{can}}$
- Step 2：$g_{\text{I}}$ 尚未被 target model 验证，用 draft model Step 1 的输出 $a_{\text{I}}$ 替代
- Step 3 及后续：同理，用前一步的 $a$ 替代未经验证的 $g$

**Verification 阶段**：将 draft tree 传给 target model 做一次 forward pass，用 tree attention 并行验证所有 draft tokens，按 speculative sampling 的接受/拒绝规则处理。

### 8.2 关键公式

**Feature 融合**：
$$g = \text{FC}([l; m; h]) \in \mathbb{R}^{k}$$

其中 $[l; m; h] \in \mathbb{R}^{3k}$ 是三层 feature 的 concatenate。

**输入构造**：
$$\text{input} = \text{FC}([g; e]) \in \mathbb{R}^{k}$$

其中 $e$ 是 sampled token 的 embedding。

**Draft model 输出**：
$$a = \text{DecoderLayer}(\text{input})$$

**Speculative sampling 接受概率**：
$$\text{accept}(\hat{t}_{j+i}) = \min\left(1, \frac{p_{j+i}(\hat{t}_{j+i})}{\hat{p}_{j+i}(\hat{t}_{j+i})}\right)$$

### 8.3 模型与数据流

- **Target model**：不修改任何权重，仅在 forward pass 时记录 low/mid/high-level feature。
- **Draft model**：单层 Transformer decoder + 两个 FC 层（feature 融合 + embedding 拼接），复用 target model 的 LM head。
- **Draft tree**：继承 EAGLE-2 的 context-aware dynamic draft tree，depth=8，expansion nodes=10。

### 8.4 系统架构图

![Figure 1: EAGLE-3 推理 pipeline](sources/2503.01840-eagle-3-scaling-up/arxiv/figs/method.pdf)

**图解**：该图展示了 EAGLE-3 draft model 的三个推理步骤。左侧是 Step 1，输入来自 target model 的 low/mid/high-level features ($l$, $m$, $h$) 经 FC 层融合为 $g$，拼接 embedding $e$ 后送入单层 Decoder 产生输出 $a$，再经 LM head 采样得到 draft token。中间是 Step 2，注意 Step 1 的输出 $a_{\text{I}}$ 替代了未经验证的 $g_{\text{I}}$ 作为输入。右侧是 Step 3，同理用 $a_{\text{do}}$ 替代 $g_{\text{do}}$。**为什么这张图重要**：它清晰展示了 EAGLE-3 与 EAGLE 的核心差异——输入不再是单一的 top-layer feature，而是三层融合后的 $g$；同时展示了 draft model 输出如何在多步生成中被自身复用，这是 training-time test 要解决的训练-推理一致性问题的直接可视化。

### 8.5 Training-time Test 机制

![Figure 3: 训练时 attention mask 示意图](sources/2503.01840-eagle-3-scaling-up/arxiv/figs/train.pdf)

**图解**：该图展示了 training-time test 的三步训练过程及其 attention mask 设计。左图是 Step 1 的标准训练：输入 "How can I"，attention mask 为下三角矩阵，输出 "are we do"。中图是 Step 2 的模拟训练：输入变为 Step 1 的输出 "are we do"（蓝色 tokens），它们与原始训练数据 "How can I"（灰色 tokens）之间形成树状上下文关系，attention mask 相应调整为对角形式（仅在与原始数据做 key 时有连接）。右图是 Step 3 的二次模拟：输入进一步变为 "we 1 2 3"（黄色 tokens），延续树状依赖。**为什么这张图重要**：这张图是理解 training-time test 技术的关键——它展示了 draft model 如何在训练时就学会处理自己输出的估计值，而不是只在推理时才遇到这个问题。attention mask 的特殊设计（对角连接 + 仅与原始数据做全连接）是实现这一训练策略的技术核心。

### 8.6 训练方法对比

![Figure 5: Training-time test 与其它方法的对比](sources/2503.01840-eagle-3-scaling-up/arxiv/figs/nofe.pdf)

**图解**：该图用三行对比展示了 EAGLE-3 的两个核心改进的动机。上行是原始 EAGLE：draft model 在 Step 1 预测 feature $\hat{f}_{t+1}$，loss 包含 $l_{\text{fea}} + l_{\text{token}}$，feature prediction 是一个约束。中行是去掉 feature constraint 后：loss 只剩 $l_{\text{token}}$，输入变为无约束向量 $a$，Step 1 的 $0$-$\alpha$ 提升但 Step 2 的 $1$-$\alpha$ 骤降（因为 $\hat{a}_{t+1}$ 偏离训练分布）。下行是 EAGLE-3 的完整方案：加入 training-time test，将 Step 1 也纳入训练过程，同时用多层 feature fusion 替代 top-layer feature。**为什么这张图重要**：这是全文叙事的核心图——它将 "EAGLE 不 scaling" 这个模糊问题分解为两个可诊断、可操作的子问题，每个子问题对应一个改进，形成清晰的因果链。

### 8.7 算力资源需求

论文未明确给出训练算力信息。根据线索估算：
- 训练数据：ShareGPT（~68K 条）+ UltraChat-200K（~464K 条），由 target model 生成响应
- Draft model 仅含单层 Transformer decoder + 两个 FC 层，参数量极小（相对于 target model 可忽略不计）
- 训练需要调用 target model 生成 ground-truth response（约 532K 条数据），这是一次性的推理成本
- 基于单层 decoder 的极简结构，训练应在单 GPU 上数小时内完成（估算）
- 推理实验涉及 4 个 target model（8B/13B/70B），H100 和 RTX3090 两种 GPU（估算）

## 9. 实验

### 9.1 评测数据集

| 数据集 | 任务类型 | 规模 | 说明 |
|--------|---------|------|------|
| MT-bench | 多轮对话 | 80 道题 | LLM-as-a-judge 评测，评估对话能力 |
| HumanEval | 代码生成 | 164 道题 | Python 函数补全，评估代码能力 |
| GSM8K | 数学推理 | 1319 道题 | 小学数学应用题，评估推理能力 |
| Alpaca | 指令跟随 | 805 条 | 多样化指令，评估通用能力 |
| CNN/Daily Mail | 摘要生成 | ~11K 条 | 新闻摘要，评估长文本能力 |

所有任务使用同一套 draft model 权重，未针对特定任务微调。

### 9.2 评测指标

- **Speedup Ratio**：相对于 vanilla autoregressive decoding 的实际加速比。越大越好。
- **Average Acceptance Length $\tau$**：每个 drafting-verification 周期平均接受的 token 数。$\tau$ 越大意味着每次验证能"通过"更多 draft token，直接反映 draft model 的近似质量。
- **Acceptance Rate $n$-$\alpha$**：当输入包含 $n$ 个 draft model 自身的估计值时的接受率。用于诊断 error accumulation 问题——如果 $n$-$\alpha$ 随 $n$ 增大而快速下降，说明 draft model 无法处理自己的估计值。

### 9.3 主实验结果

![Figure 2: 不同方法的 speedup ratio 对比（temp=0）](sources/2503.01840-eagle-3-scaling-up/arxiv/figs/r1.pdf)

**图解**：该图展示了在 temperature=0 条件下，不同 speculative decoding 方法在 chat model（MT-bench）和 reasoning model（GSM8K）上的 speedup ratio。EAGLE-3（红色）在所有 target model 上均显著高于 EAGLE-2（绿色）和 HASS（橙色）。在 Vicuna 13B 上达到约 5.6x，在 LLaMA 3.1 8B 上约 4.4x，在 LLaMA 3.3 70B 上约 4.1x，在 DeepSeek-R1-Distill 8B 上约 4.1x（GSM8K）。**为什么这张图重要**：这是论文的核心结果图——它直观展示了 EAGLE-3 相对于所有 baseline 的一致性优势。值得注意的是 EAGLE-3 与 HASS 的对比：两者在训练时都模拟多步生成，但 EAGLE-3 去掉了 feature prediction loss 并使用多层 feature fusion，带来了显著的性能差距。

**Table 1 关键数据**（Temperature=0）：

| Model | Method | MT-bench Speedup | Mean Speedup | Mean $\tau$ |
|-------|--------|-----------------|--------------|-------------|
| Vicuna 13B | EAGLE-2 | 4.26x | 4.22x | 4.83 |
| Vicuna 13B | EAGLE-3 | **5.58x** | **5.51x** | **6.62** |
| LLaMA 3.1 8B | EAGLE-2 | 3.16x | 3.23x | 4.11 |
| LLaMA 3.1 8B | EAGLE-3 | **4.40x** | **4.44x** | **6.23** |
| LLaMA 3.3 70B | EAGLE-2 | 2.83x | 2.85x | 3.78 |
| LLaMA 3.3 70B | EAGLE-3 | **4.11x** | **4.12x** | **5.88** |
| DSL 8B | EAGLE-2 | 2.92x | 3.26x | 3.92 |
| DSL 8B | EAGLE-3 | **4.05x** | **4.16x** | **5.84** |

EAGLE-3 在所有配置下均一致优于 EAGLE-2，平均加速比提升约 30-45%。HumanEval 上表现最好（代码模板多，draft 容易），最高达 6.47x。

**Acceptance Rate 分析**：

![Figure 4: EAGLE vs EAGLE-3 的 acceptance rate 对比](sources/2503.01840-eagle-3-scaling-up/arxiv/figs/alpha.pdf)

**图解**：该图展示了 EAGLE 和 EAGLE-3 在 MT-bench（LLaMA 3.1 8B）上随 $n$ 变化的 acceptance rate。EAGLE 的 acceptance rate 随 $n$ 增大快速下降（从 0-$\alpha$≈0.85 降到 4-$\alpha$≈0.55），而 EAGLE-3 的曲线几乎平坦（0-$\alpha$≈0.94 到 4-$\alpha$≈0.91）。**为什么这张图重要**：这是 training-time test 有效性的最直接证据——EAGLE 的 error accumulation 问题（draft model 无法处理自己的估计值）在 EAGLE-3 中几乎被消除。这也解释了为什么 EAGLE-3 的 $\tau$ 远高于 EAGLE：不仅第一个 draft token 更准，后续 token 的接受率也不衰减。

### 9.4 消融实验

**Table 2 消融结果**（LLaMA-Instruct 3.1 8B）：

| Method | MT-bench Speedup | MT-bench $\tau$ | GSM8K Speedup | GSM8K $\tau$ |
|--------|-----------------|-----------------|---------------|---------------|
| EAGLE-2 (baseline) | 3.16x | 4.05 | 3.39x | 4.24 |
| + remove fea con | 3.82x | 5.37 | 3.77x | 5.22 |
| + fused features (EAGLE-3) | **4.40x** | **6.13** | **4.48x** | **6.23** |

**分析**：
- "Remove fea con"（去掉 feature prediction constraint）贡献了 +21% 的 speedup 提升（MT-bench），是最大的单项改进。
- "Fused features"（多层 feature fusion）在此基础上再贡献 +15%。
- 两个改进的叠加效果（3.16x→4.40x，+39%）大于各自单独效果之和，说明两者有正交互作用。

**图解**：上图展示了 speedup ratio 随训练数据量（相对 ShareGPT 的倍数）的变化。EAGLE-3（蓝色实线）呈持续上升趋势，而 EAGLE（灰色虚线）和 HASS（橙色虚线）在数据量增大后趋于平坦。下图展示了 average acceptance length 的相同趋势。**为什么这张图重要**：这是论文声称 "discovery of a scaling law" 的核心证据——EAGLE-3 的新架构使得 draft model 能够从更多训练数据中持续获益，而 EAGLE 的架构存在天花板。但需注意：(1) 仅在 LLaMA 3.1 8B + MT-bench 上展示；(2) x 轴的 scaling range 有限（最大约 7x ShareGPT）。

### 9.5 结果分析

**作者的分析**：
- EAGLE-3 在所有任务上一致优于 baseline，但不同任务的收益不同。HumanEval（代码生成）收益最大，因为代码模板的可预测性高。GSM8K（数学推理）对 DeepSeek-R1-Distill 模型收益最大，可能是因为训练时使用了 OpenThoughts-114k-math 数据集。
- EAGLE-3 在 SGLang 中的吞吐优势在大 batch 下依然显著（bs=64 时 +38%），而 EAGLE 在 bs=24 时已开始降低吞吐。作者将此归因于 EAGLE-3 更高的 acceptance length 减少了 memory-bound 的等待时间。

**Agent 的分析**：

1. **Scaling law 的证据局限**：Figure 2 的 scaling curve 仅在单一模型单一任务上展示，将其称为 "scaling law" 为时尚早。真正的 scaling law 需要在多模型族、多规模、多任务上验证。从数据看，EAGLE 在数据量 1x→3x 时还有小幅提升，3x 之后才趋于平坦——如果 EAGLE-3 的曲线在更大数据量下也出现类似拐点，那 "scaling law" 的说法就不成立。

2. **消融实验未解耦架构与数据**：Table 2 的消融是在 EAGLE-3 的完整训练数据量下进行的。如果在 EAGLE-2 的原始数据量下做 "remove fea con" 的消融，效果可能不同。论文需要一个 2×2 的消融矩阵（架构 × 数据量）来彻底解耦两个因素。

3. **吞吐实验的 decoding 策略差异**：主实验用 tree structure（depth 8），SGLang/vLLM 实验用 chain-only（length 2-3）。从 Table 1 和 Table 3 的数据差距看，tree structure 贡献了约 2x 的额外 speedup。论文应明确说明这一差异，否则读者可能误将 tree-based 的 speedup 数据当作 chain-based 的吞吐提升的参考。

4. **Draft model 容量瓶颈**：单层 decoder 的极简设计在 8B/13B 模型上效果良好，但在 70B 模型上 EAGLE-3 的 speedup（4.11x）相对于 8B 模型（4.40x）反而略低。这可能暗示 draft model 容量随 target model 增大而不足——但论文未讨论这个趋势。
